# Astranomy 接口设计笔记

来源：NVIDIA SRL，*Astranomy: An empirical study of GPT-6 Astra as a native robot policy*（CoRL 2026 LBR，2026-10-14），https://research.nvidia.com/labs/srl/projects/astranomy/

本文用我们自己的话整理它的接口设计和实验结论，作为 EvoAB 写 prompt 和工具 schema 的依据。我们自己的 prompt 要在这些结构上重写，不照抄原文。

## 1. 三种策略形态

| 形态 | 回路 | 每次调用的输出 | RoboLab-120 SR | 成本 / 延迟 |
|---|---|---|---|---|
| Direct | 无状态 API 调用，没有会话 | 3–15 个绝对 EEF 目标，长度由模型自选 | 66.3% | 16 万 token / $1.96 每回合，18.6 s 每次调用 |
| Agentic | 持久 Codex 会话，保留完整历史 | 1 个绝对 EEF 目标，保持 1–5 个控制步 | 74.8% | 3090 万 token / $36.4 每回合，13.4 s |
| Orchestrated | Cosmos3-Nano 每次提议 15 步，Astra 审核 | 接受、编辑提议，或改发 EEF 目标 | 66.5% | 1100 万 token / $17.7，Astra 11.5 s + WAM 2.7 s |

公共设置：
- GPT-6 Astra，`medium` reasoning；
- 3 个相机（左肩、右肩、腕部），每张缩到 384×216；
- 15 Hz 控制，推理时仿真暂停；
- 每次调用最多 8192 个补全 token。

## 2. Prompt 的结构（按段落拆开，可以独立开关）

每一段都只回答一个问题。消融实验就是按段增删做的。

1. **身份**：控制什么机器人（DROID = Franka Panda + Robotiq 2F-85）、观测是什么（按时间排序的 RGB 帧 + 同步的本体状态）、总体要求（每次运动后重看三个视角；动作小而审慎；避开桌面、自身和无关物体）。
2. **坐标约定**：
   - 根坐标系三轴的物理朝向；
   - 动作位姿描述的是哪个 link（法兰，不是指尖）；
   - 哪些状态字段与动作同一约定、哪些是兼容字段不能混用；
   - 四元数顺序（wxyz）和旋转方向的约定。
3. **动作格式**：
   - 每一行动作的语义：绝对位姿 + 夹爪 0/1；
   - 客户端会做哪些处理（归一化四元数、限步长），并提醒这些检查不能代替规划。
4. **执行时序**：
   - 每行动作对应多长的控制间隔；
   - 发出目标不等于到达目标；
   - API 耗时不推进仿真；
   - 每步平移和转角的上限；
   - 实际运动可能更小；
   - 用测量到的位姿判断是否到位。
5. **输出要求**：
   - 只调一次指定的工具；
   - 动作数量的范围；
   - 每一步都要显式给出，宿主不插值；
   - 由模型决定下次重新看图前执行多少步。
6. **夹爪几何（可选段）**：
   - 指垫沿法兰局部哪个轴伸出、两指沿哪个轴分开；
   - 一张"开合度 g → 法兰到指垫中点的距离 d、内侧间隙"的表（5 行，可插值）；
   - 两条换算公式：法兰 ↔ 指垫；
   - 两种姿态下的数值示例；
   - 强调这些是几何参考，不是抓取检测。
7. **相机标定（可选段）**：
   - 每个相机的父坐标系、平移、四元数，以及外参公式；
   - 腕部相机随法兰运动，肩部相机固定在根坐标系；
   - 腕部相机视线偏离接近轴的角度，以及它在向下姿态时的根坐标方向；
   - 归一化内参和投影公式；
   - 指垫中点在腕部图像里的大致位置（不在图像中心）；
   - 提醒：单个像素只给出一条射线；物体在图像中心不代表在两指之间。
8. **规划指令（可选段）**：先拆成几个子目标，跟踪当前子目标，按观测结果修订。
9. **工具使用边界（Agentic）**：
   - 记忆和分析工具不会动机器人；
   - 禁止读仿真内部状态；
   - 每轮以且只以一个动作提议结束；
   - 动作由宿主校验后执行；
   - 终止只由环境判定，没有"done"动作。

## 3. 观测 JSON

基础版（每个 effector 一项）：

```json
{
  "embodiment": "droid",
  "orientation_convention": "extrinsic xyz fixed-axis roll/pitch/yaw, degrees",
  "effectors": {
    "arm": {"root_frame": "DROID robot root", "position_m": [x, y, z],
            "roll_pitch_yaw_deg": [r, p, y], "gripper": "open"}
  }
}
```

扩展版额外提供：
- `geometry_state.ee_pos`、`geometry_state.ee_quat`（wxyz，与动作约定一致）；
- `geometry_state.gripper_pos`（连续开合度，0 开 1 闭，与二值夹爪指令区分）；
- 7 个关节角 `arm_joint_pos`。

历史观测各自带当时的状态。

每段执行之后返回：
- 新的图片；
- 测量状态；
- 剩余步数预算；
- 环境给出的子任务进度；
- （可选）位置和姿态跟踪误差，以及指令夹爪和测量夹爪的对比。

## 4. 工具 schema

Agentic 动作工具（来自公开的调用记录）：

```json
{"name": "execute_eef_target",
 "arguments": {
   "target": {"position": [0.40, -0.012, 0.446],
              "quaternion_wxyz": [0.7071068, 0, 0.7071068, 0],
              "gripper_closed": false},
   "steps": 5,
   "reason": "Approach above the red bottle estimated from both shoulder views."}}
```

- 宿主约束：目标离最新测量位姿不超过 0.05 m 和 0.35 rad。
- 每个控制步重算阻尼最小二乘 IK，限幅：位置误差 0.02 m、转角 0.1 rad、每关节 0.05 rad。
- 整段保持同一个目标，宿主不插值。

Direct 动作工具：`emit_eef_actions`，参数是 3–15 行 `[x, y, z, qw, qx, qy, qz, gripper]`。

Agentic 的辅助工具：
- `memory_*` 系列：取回历史观测、动作历史和笔记；
- 可选的 shell / Python 工作区：`workspace.json` 给出图片路径，`scratch/` 放脚本和裁图，`NOTES.md` 记录进度和估计值。

公开记录里能看到的典型计算：
- 用两个肩部视角三角化物体位置，结果与模型目测相差几毫米；
- 用最近 11 次"末端位移 ↔ 像素位移"做线性拟合。

## 5. 消融结论（30 任务子集，每任务 5 回合）

| 因素 | 结果 | 对 EvoAB 的含义 |
|---|---|---|
| 动作表示（Direct） | 绝对 EEF 72.7% > delta 66.0% > relative 64.7% > 关节 48.7% > B-spline 37.3% | 默认用绝对 EEF；其他表示作为可选接口 |
| 动作表示（Agentic） | EEF 86.0% ≈ 关节 84.0% | Agentic 对动作表示不敏感 |
| 块长度 | 3–15 比 16–32 高 6pp；后者调用次数少 62%，完成时间相近 | 块长度由模型自选，范围可配置 |
| 几何信息（Direct） | 基础 19.3% → +夹爪 35.3% → +相机 62.7% → 两者都有 72.7% | **几何片段必须由环境提供**，是 Direct 的关键 |
| 几何信息（Agentic） | 83.3% → 86.0% | 影响小，但去掉后多用 14.7% 的步数 |
| 观测历史（Direct） | 只给当前帧 49.3%；给 3 帧 72.7%；更多更密没有提升 | 默认 t−14、t−7、t |
| 会话历史（Agentic，23 任务） | 完整历史 100% > 完整文本 + 近期图片 95.7% > 只有文本历史 87.0% > 近期文本和图片 73.9% > 只有图片历史 56.5% | **保留完整文本历史最重要** |
| 任务描述 | Direct 下模糊指令低 8.7pp；Agentic 几乎不受影响；视频示范 87.9% vs 语言 90.0% | ICL 可选 |
| 模型 | Astra 72.7%、Sol 33.3%、Opus 5.5 25.3%、Luna 2.0% | 模型差异远大于接口差异 |
| reasoning effort | xhigh 74.5% vs medium 72.7%，但延迟是 2.6 倍、成本是 2.2 倍 | 默认 medium |
| 可选工具 | 86.0% → 88.0%（每回合平均 19.7 次工具调用） | 默认关闭，可开 |
| 规划指令 | 有 86.0%，没有 90.0%，劝阻规划 81.0% | 默认关闭，可开 |
| 运动误差反馈 | 85.9% vs 85.2% | 可选 |
| 扩展接口整体 | 80.0% → 86.0%（McNemar p = 0.108） | 扩展观测字段 + 几何 + 执行说明一起提供 |

## 6. Orchestrated 的观察

- Astra 干预的步数占全部仿真步的 14.5%。
- 干预原因：抓取失败 64.4%、目标或计划错误 20.2%、放置或操作失败 11.4%、搬运失败 3.7%。
- 用 WAM 生成动作提议，没有明显优于 Astra 自己出动作。
- 待研究的问题：哪些决策交给策略模型、什么时候审核、增加的延迟值不值。

## 7. 失败模式与局限

- 主要难点是把"尝试"变成完成的抓取、搬运或放置：在物体周围反复微调、把物体碰开、放错容器、恢复动作重复无效。
- 推理延迟占回合总时长的 97%。论文的评测前提是推理时仿真暂停，所以没有测试实时性。
- 每任务只有 5 回合，大多数差异没有统计显著性。
- 只覆盖抓放类任务，不含插接、装配和高动态任务。

## 8. 落到 EvoAB 的具体要求

1. `RobotSpec.interface_facts()` 输出 `identity`、`frames`、`timing`、`gripper_geometry`、`camera_calibration`、`caveats` 六块，每块可以单独开关，便于做同样的消融。
2. 观测序列化器统一输出第 3 节的 JSON，并可配置基础版或扩展版。
3. 动作工具的 schema 用自解释的字段名，必须有 `reason`。宿主做范围校验，校验失败的结果要返回给模型。
4. `EvoAgentLoop` 的历史策略可配置：完整、完整文本 + 近期图片、只有文本、只有图片。
5. 每次调用记录 token、美元和延迟，回合级别汇总到复现卡片。
